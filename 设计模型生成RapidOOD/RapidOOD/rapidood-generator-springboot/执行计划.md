# com.rm2pt.rapidood.generator → Spring Boot 迁移计划

> **范围**：仅迁移 `com.rm2pt.rapidood.generator` 的 **ATL 类图生成链路**（`.remodel` → `.cd`）  
> **不含**：`DomainModelDesignDialog` 中的 LLM 职责分配 / 领域划分（原插件第二阶段）  
> **周期**：3 个阶段 × 每阶段 2 天 = **共 6 个工作日**  
> **架构说明**：见同目录 `generator-架构分析.md`

---

## 0. 迁移对象清单

### 0.1 需迁移的能力

| 原组件 | 职责 | Spring Boot 对应 |
|--------|------|------------------|
| `RunATL.java` | REMODEL EMF → ATL → ClassDiagram EMF | `AtlTransformService` |
| `DomainDesignModelGeneratorHandler` | 编排：加载 remodel → ATL → 加载/序列化 cd | `DesignGenerateService` |
| `GenerateClassDiagram.asm` | ATL 编译产物（运行时实际使用） | `classpath:atl/GenerateClassDiagram.asm` |
| `plugin.xml` | Eclipse 右键菜单 | `@RestController` |

### 0.2 明确不迁移

| 原组件 | 原因 |
|--------|------|
| `DomainModelDesignDialog.java` | LLM 增强，超出本次范围 |
| `SampleHandler.java` | 示例代码 |
| `enhanceModel()` 调用链 | 依赖 Swing + LLM |

### 0.3 依赖引入策略

| 依赖 | 用途 | 迁移策略 |
|------|------|----------|
| `net.mydreamy.requirementmodel` | 解析 `.remodel` | Maven 模块 `rapidood-requirement-model` |
| `com.rm2pt.rapidood.cd` | 解析/序列化 `.cd` | Maven 模块 `rapidood-classdiagram-model`（无 `.ui`） |
| `org.eclipse.m2m.atl.*` | ATL 转换 | Eclipse Orbit Maven |
| `org.eclipse.emf.*` | EMF 运行时 | Eclipse Orbit Maven |
| `org.eclipse.xtext` | DSL Standalone | 不含 `xtext.ui` |
| `org.eclipse.ui.*` / Swing / Gson | IDE 与 LLM UI | **不引入** |

### 0.4 不在本 6 天范围内

- `com.rm2pt.rapidood.optimization`（设计优化插件）
- LLM 相关 API 与配置
- Web 前端 SPA（curl / Postman / Swagger 验收即可）
- 序列图 `.sd` 自动生成

### 1.1 交付 API

**I/O 方式**：不从 HTTP 上传文件；**输入**读取服务器本地路径上的 `.remodel`，**输出**写入本地目录下的 `.cd` 文件（与原 Eclipse 插件 `{项目}/DesignModel/{同名}.cd` 一致）。

#### 默认路径配置（`application.yml`）

```yaml
rapidood:
  paths:
    # 方式 A：直接指定单个输入文件（适合固定案例）
    input-file: /data/rapidood/input/CoCoME.remodel
    # 方式 B：或指定输入目录，API 请求体传文件名（见下文）
    # input-dir: /data/rapidood/input
    # 输出目录；默认与 Eclipse 相同逻辑：与输入同级的 DesignModel 子目录
    output-dir: /data/rapidood/output/DesignModel
    # 若为 true：output-dir 忽略配置，改为 {input-file 所在目录}/DesignModel/
    output-follow-input: true
```

**输出文件命名规则**：

```
输入：/data/rapidood/input/CoCoME.remodel
输出：/data/rapidood/input/DesignModel/CoCoME.cd   # output-follow-input: true 时

或（output-follow-input: false 时）：
输出：{rapidood.paths.output-dir}/CoCoME.cd
      即 /data/rapidood/output/DesignModel/CoCoME.cd
```

#### API 列表

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/generate/class-diagram` | 按本地路径读 `.remodel`，ATL 生成后写入本地 `.cd` |
| GET | `/actuator/health` | 健康检查 |

#### POST `/api/v1/generate/class-diagram`

**请求体**（JSON，字段均可选；未传时使用 `application.yml` 默认值）：

```json
{
  "inputPath": "/data/rapidood/input/CoCoME.remodel",
  "outputDir": "/data/rapidood/input/DesignModel"
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `inputPath` | 否 | 本地 `.remodel` 绝对路径；缺省用 `rapidood.paths.input-file` |
| `outputDir` | 否 | 本地输出目录；缺省按 `output-dir` / `output-follow-input` 规则计算 |

**成功响应**（200）：

```json
{
  "inputPath": "/data/rapidood/input/CoCoME.remodel",
  "outputPath": "/data/rapidood/input/DesignModel/CoCoME.cd",
  "fileName": "CoCoME.cd",
  "success": true
}
```

响应中的 `outputPath` 即为生成结果的**本地落盘位置**；如需查看内容，直接打开该文件或使用 `cat`。

**失败响应**（4xx/5xx）：输入文件不存在、非 `.remodel`、ATL 失败、输出目录不可写等。

## 2. 三阶段执行计划（每阶段 2 天）

---

## 阶段一（第 1～2 天）：工程骨架 + ATL 无头运行

**目标**：JUnit 中完成 `remodel → ClassDiagram EMF`，不启动 Eclipse。

### 第 1 天：初始化与依赖

| 时段 | 任务 | 产出 |
|------|------|------|
| 上午 | Spring Boot 3.2 + Java 17 多模块父 POM | `mvn -q validate` 通过 |
| 上午 | 配置 Eclipse Maven 仓库（EMF、ATL、Xtext） | 依赖可解析 |
| 下午 | 迁入 `com.rm2pt.rapidood.cd` → `rapidood-classdiagram-model` | `ClassDiagramStandaloneSetup` 可用 |
| 下午 | 迁入 REMODEL → `rapidood-requirement-model`（或 Spike 用 XMI） | `REMODELStandaloneSetup` 可用 |

**检查点**：

- [x] 两个 StandaloneSetup 在 `@Test` 中可执行且不重复注册 EMF

### 第 2 天：重构 RunATL

| 时段 | 任务 | 产出 |
|------|------|------|
| 上午 | `GenerateClassDiagram.asm` → `resources/atl/` | classpath 可加载 |
| 上午 | `AtlTransformService`：签名 `transform(Path remodel, Path outputCd)` | 无 `IProject` |
| 下午 | `file:` URI + `ClassLoader` 加载 asm（去掉 `Platform.getBundle`） | 纯 JVM |
| 下午 | 单元测试：`testdata/*.remodel` → `target/*.cd` | 测试绿 |

**改造要点**：

```java
InputStream asm = getClass().getResourceAsStream("/atl/GenerateClassDiagram.asm");
URI inUri = URI.createFileURI(remodelPath.toAbsolutePath().toString());
extractor.extract(outModel, outputPath.toAbsolutePath().toString());
```

**阶段一退出标准**：

- [x] Maven `test` 通过 ATL 转换
- [x] 输出可被 Xtext 解析为合法 `ClassDiagram`

---

## 阶段二（第 3～4 天）：编排服务 + 文本序列化

**目标**：`DesignGenerateService.generate(remodel)` 返回完整 `.cd` 文本，等价原 Handler **ATL 前半段**。

### 第 3 天：模型加载与序列化

| 时段 | 任务 | 产出 |
|------|------|------|
| 上午 | `RequirementModelService.load(Path)` | 返回 `RequirementModel` / `Resource` |
| 上午 | `ClassDiagramService.load/save(Path)` | cd 读写 |
| 下午 | `serializeToText(ClassDiagram)`（Serializer 或 NodeModelUtils） | PlantUML 子集字符串 |
| 下午 | `EmfXtextConfig`：单例注册 StandaloneSetup | 避免重复注册 |

### 第 4 天：DesignGenerateService + 回归测试

| 时段 | 任务 | 产出 |
|------|------|------|
| 上午 | `DesignGenerateService`：load → ATL → load cd → serialize | `GenerateResultDto` |
| 上午 | 临时目录替代 `DesignModel/`（`Files.createTempDirectory`） | 无 workspace 依赖 |
| 下午 | 黄金测试：CoCoME 等 1～2 案例，对比类/关系数量 | `src/test/resources/golden/` |
| 下午 | 确认无 `enhanceModel`、无 Swing、无 LLM 引用 | 代码审查通过 |

**Handler → Service 映射**：

| 原步骤 | 新实现 |
|--------|--------|
| `createPlatformResourceURI` | `URI.createFileURI` |
| `RunATL.run(..., project)` | `atlTransformService.transform(...)` |
| `enhanceModel(...)` | **删除，不调用** |
| `ClassDiagramStandaloneSetup` + save | `DesignGenerateService` 返回文本 |

**阶段二退出标准**：

- [x] `DesignGenerateService.generate(Path)` 返回 `@startuml ... @enduml`
- [x] 无 `org.eclipse.ui`、`org.eclipse.core.resources`、`SwingUtilities`

## 8. 启动与调用

```bash
# 1. 准备本地输入（示例路径，与 application.yml 一致）
mkdir -p /data/rapidood/input/DesignModel
cp testdata/CoCoME.remodel /data/rapidood/input/

# 2. 启动服务
cd rapidood-generator-springboot/rapidood-generator-api
mvn spring-boot:run

# 3. 触发转换（使用 yml 默认 input-file，或显式传路径）
curl -s -X POST http://localhost:8080/api/v1/generate/class-diagram \
  -H "Content-Type: application/json" \
  -d '{"inputPath":"/data/rapidood/input/CoCoME.remodel"}'

# 4. 查看输出（响应 outputPath 指向的位置，默认如下）
cat /data/rapidood/input/DesignModel/CoCoME.cd
```
